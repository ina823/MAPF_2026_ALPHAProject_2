
# 로봇 ROS 인터페이스 초안 (2026-10-30)

## 1. 목적

MAPF Global Runner와 실제 로봇의 연결에 필요한
통신 인터페이스 및 안전 요구사항을 정리한다.

현재 로봇 기종과 ROS 환경은 확정되지 않았으므로
아래 내용은 ROS 2 기준의 초기 설계안이다.

## 2. 필요한 인터페이스

### 2.1 이동 명령: cmd_vel
- 역할: 로봇의 선속도 및 각속도 제어
- 메시지 형식: geometry_msgs/msg/Twist 또는
  TwistStamped (로봇 Driver 확인 필요)
- MAPF Action을 바로 전달하지 않음
- 격자 경로를 실제 이동 명령으로 변환하는
  별도 제어 계층 필요

### 2.2 위치 추정: odom
- 역할: 로봇의 위치, 방향, 속도 정보 수신
- 대표 메시지: nav_msgs/msg/Odometry
- Runner의 예상 위치와 실제 위치 비교에 활용
- 실제 위치의 격자 좌표 변환 방법은 추후 확정

### 2.3 좌표 변환: TF
- 역할: 좌표계 사이의 위치 관계 관리
- 검토할 좌표계: map, odom, base_link
- /tf, /tf_static 제공 여부 확인
- 다중 로봇에서는 각 로봇의 프레임 이름
  충돌 방지 필요

### 2.4 긴급 정지: E-stop
- CBS timeout / invalid_path 발생 시 이동 차단
- 예상 위치와 실제 위치 불일치 시 이동 차단
- 소프트웨어에서 명령 차단 및 정지 요청 필요
- 실제 E-stop은 하드웨어 안전 기능과 구분
- cmd_vel=0만으로 하드웨어 E-stop을
  대체할 수 없음

## 3. 인아 Runner와의 연결

1. Runner가 로봇의 현재 상태를 수신한다.
2. IL 또는 CBS가 다음 경로를 결정한다.
3. 경로를 로봇 제어 명령으로 변환한다.
4. 실제 위치를 수신한다.
5. 예상 위치와 실제 위치를 비교한다.
6. 이상 발생 시 추가 명령을 차단한다.
